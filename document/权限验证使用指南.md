# 权限验证使用指南

## 1. 系统权限架构概述

本系统采用基于 JWT 和角色的权限验证机制，通过自定义注解`@RequirePermission`和权限拦截器`PermissionInterceptor`实现接口级别的权限控制。

### 1.1 核心组件

- **@RequirePermission 注解**：标记需要权限验证的方法或类
- **PermissionInterceptor 拦截器**：拦截带有@RequirePermission 注解的请求，进行权限验证
- **权限枚举类**：定义系统中的角色和权限
- **权限常量**：统一管理权限编码

## 2. @RequirePermission 注解使用方法

### 2.1 注解属性

```java
@Target({ ElementType.TYPE, ElementType.METHOD })
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface RequirePermission {
    /** 需要的权限编码 */
    String value() default "";

    /** 是否需要登录 */
    boolean needLogin() default true;

    /** 是否需要权限验证 */
    boolean needPermission() default true;

    /** 权限验证失败时的错误信息 */
    String message() default "权限不足";
}
```

### 2.2 使用场景

#### 2.2.1 基本登录验证

只需要用户登录，不需要特定权限的接口：

```java
@RestController
@RequestMapping("/api/v1/user")
public class UserProfileController {

    // 只需要登录即可访问，不需要特定权限
    @RequirePermission(needPermission = false)
    @GetMapping("/profile")
    public Result<UserInfo> getUserProfile() {
        // 获取当前登录用户信息
        // ...
    }
}
```

#### 2.2.2 用户端基本权限

所有登录用户都有的基本权限：

```java
import com.baffang.common.constant.PermissionConst;

        // ...
    }

```

#### 2.2.7 方法级别覆盖类级别权限

方法上的注解可以覆盖类上的注解：

```java
import com.baffang.common.constant.PermissionConst;

@RestController
@RequestMapping("/api/v1/admin")
@RequirePermission(PermissionConst.ADMIN_COMMON_ADMIN) // 类级别：需要管理员权限
public class AdminController {

    @GetMapping("/dashboard")
    public Result<DashboardInfo> getDashboard() {
        // 需要管理员权限
        // ...
    }

    @RequirePermission(needPermission = false) // 方法级别：只需要登录
    @GetMapping("/public-info")
    public Result<PublicInfo> getPublicInfo() {
        // 只需要登录即可访问
        // ...
    }
}
```

## 3. 权限编码规则

### 3.1 用户端权限编码

| 权限编码                           | 适用角色                 | 说明                       |
| ---------------------------------- | ------------------------ | -------------------------- |
| PermissionConst.USER_COMMON_USER   | 所有用户                 | 基本权限，所有登录用户都有 |
| PermissionConst.USER_CAR_OWNER     | VEHICLE_OWNER, ALL_OWNER | 车辆查看和管理权限         |
| PermissionConst.USER_STATION_OWNER | STATION_OWNER, ALL_OWNER | 充电桩查看和管理权限       |
| PermissionConst.USER_ALL_OWNER     | ALL_OWNER                | 车辆和充电桩所有权限       |

| 权限编码                               | 适用角色                                      | 说明           |
| -------------------------------------- | --------------------------------------------- | -------------- |
| PermissionConst.ADMIN_COMMON_ADMIN     | ADMIN, SUPER_ADMIN                            | 普通管理员权限 |
| PermissionConst.ADMIN_SUPER_ADMIN      | SUPER_ADMIN                                   | 超级管理员权限 |
| PermissionConst.ADMIN_AUDITOR          | AUDITOR, CUSTOMER_SERVICE, ADMIN, SUPER_ADMIN | 审核员权限     |

| auth_vehicle | auth_charging_station | 角色          | 权限范围                                                                                                                             |
| ------------ | --------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 0            | 0                     | NORMAL        | PermissionConst.USER_COMMON_USER                                                                                                     |
| 2            | 0                     | VEHICLE_OWNER | PermissionConst.USER_COMMON_USER, PermissionConst.USER_CAR_OWNER                                                                     |
| 0            | 2                     | STATION_OWNER | PermissionConst.USER_COMMON_USER, PermissionConst.USER_STATION_OWNER                                                                 |
| 2            | 2                     | ALL_OWNER     | PermissionConst.USER_COMMON_USER, PermissionConst.USER_CAR_OWNER, PermissionConst.USER_STATION_OWNER, PermissionConst.USER_ALL_OWNER |

## 6. 权限验证流程

1. 用户/管理员登录，获取 JWT 令牌
2. 访问接口时，在请求头中携带 JWT 令牌
3. JWT 过滤器验证令牌有效性，解析用户信息
4. 权限拦截器检查请求是否带有@RequirePermission 注解
5. 如需登录验证，检查用户是否已登录
6. 如需权限验证，根据用户角色和权限编码检查是否有权限
7. 验证通过则继续处理请求，验证失败则返回相应错误信息

## 7. 注意事项

1. **权限编码一致性**：使用统一的权限常量，避免硬编码
2. **最小权限原则**：只为用户分配必要的权限
3. **接口分组管理**：按照功能模块和权限级别对接口进行分组
4. **错误信息友好性**：为不同权限验证场景提供清晰的错误信息
5. **角色与权限分离**：角色是权限的集合，权限是具体的操作许可
